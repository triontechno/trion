# TRION Phase 2 — Stage H: Isolated Guest Process Backend

**Implementation status: complete for the restricted Stage H guest profile.** Stage G's freestanding native images use Redox's real process/address-space interfaces. The kernel owns scheduling, user-mode entry, exception termination, process-manager wait status, descriptor brokering and teardown. Validation remains deferred until every Phase 2 implementation stage, including Stage J, is complete.

**Validation:** deferred until all Phase 2 implementation stages are complete. No tests, builds, fuzz campaigns, benchmarks or QEMU runs have been executed.

## Implemented source

- Native image entry uses a fresh Redox address space and kernel page mappings; original PE32+/Mach-O64 bytes are mapped with final W^X permissions.
- Native entry and stack registers are installed through the process scheme; the existing Redox scheduler and architecture context switch enter user mode.
- The native exit trampoline submits a dedicated `SYS_GUEST_EXIT` syscall carrying an 8-bit process status. The kernel records that status and transitions the restricted context to termination; existing process-manager lifecycle waits for all threads to terminate and kernel teardown releases file handles and address-space grants.
- Before native entry, inherited user and exception signal handlers are now cleared as a required operation. Failure to reset signal state aborts the launch rather than entering guest code with stale handlers.
- Kernel unhandled processor exceptions are retained in `CtxtStsBuf`. The process manager now maps x86-64 exception vectors to POSIX wait signals (SIGFPE, SIGTRAP, SIGSEGV, SIGILL, SIGBUS), instead of reporting the invalid signal number 1.
- The portable guest model provides bounded address-space mappings, checked memory access, W^X enforcement, memory/mapping quotas, process states, instruction budgets, brokered syscall events, breakpoint suspension and fault transitions.
- **Kernel-enforced syscall isolation and guest exit are implemented as a restricted baseline:** the native loader prepares policy for one address space, and the kernel activates it atomically when the pending address-space switch is committed. An uncommitted preflight is canceled when its control descriptor closes; after selection is staged, the pending switch retains the activation intent. The common dispatcher permits only `SYS_CLOSE`, a dedicated `SYS_GUEST_EXIT` carrying an 8-bit process status, and argument-free `SYS_GUEST_GETPID`/`SYS_GUEST_GETTID` identity queries; every other syscall is rejected before scheme dispatch. Guest exit cannot address an inherited descriptor or select a scheme operation. Policy activation is one-shot.
- The syscall-deny marker and aggregate CPU budget live in a monotonic policy object shared by the selected address space and its clones, so sibling contexts and cloned spaces inherit the syscall gate and consume one shared budget. When guest policy activates during an address-space switch, pre-existing sibling contexts owned by the same process are force-killed using the process scheme's normal termination path. The launching context retains its own guest-exit status; contexts owned by different process IDs are not treated as siblings.
- Guest policy activation drains the target file table before user-mode entry, including in-place exec descriptors and loader-created control handles; explicitly delegated descriptors are retained and all others are closed through their owning scheme after the context lock is released.
- **A kernel-enforced descriptor capability broker is implemented for bounded stream I/O.** The trusted supervisor writes an explicit descriptor allowlist through the target's `guest-policy` handle. The kernel validates descriptor identity, access mode and supported scheme class before activation; the address-space policy records read/write rights, and the syscall dispatcher enforces those rights for `SYS_READ`, `SYS_READ2`, `SYS_WRITE` and `SYS_WRITE2`. Closing a delegated descriptor revokes its rights. Supported handles are user schemes (including filesystem, network and userspace IPC scheme endpoints), pipes, and the kernel Serio/IRQ device schemes. All other operations remain denied; this is deliberately a pre-opened-handle model, not arbitrary path opening or unrestricted device control.
- The native PE/Mach-O loader now accepts an optional supervisor-supplied descriptor list through `ExtraInfo::guest_capability_fds`, preserves only those descriptors across the launch transition, and submits them to the kernel policy validator. Existing general exec call sites default this field to `None`, so ordinary launches remain deny-by-default until a trusted supervisor explicitly supplies grants.
- Kernel quotas are applied when the guest policy is activated: the authenticated guest address space is bound to the launching context and limited to 512 MiB of mapped grants (including fixed replacement and address-space move paths), each context's descriptor table is limited to 256 active descriptors/indices, and scheduled CPU time is aggregated against a 60-second budget on the shared guest address-space object. Address-space changes after activation are rejected unless they select the same bound space. These are conservative defaults for the current freestanding profile, not per-user configuration; descriptor quotas and accounting for sibling contexts on a different address space are not process-wide.
- Guest exit status is retained in the kernel context status report and forwarded to the process manager as a normal exit code. Existing force-kill and processor-exception reporting remains distinct.
- The proc scheme exposes a guest-specific `guest-crash` read endpoint. It returns the existing structured `CtxtStsBuf` format with `GuestFault`, `GuestExit` or `ForceKilled` status and the exception/status payload; reads before termination return `EAGAIN`, and non-guest contexts are rejected.
- The proc scheme exposes a guest-specific `guest-cancel` write endpoint. A supervisor writes the cancel command to request normal kernel force-kill scheduling; dead guests are handled idempotently. Guest process/thread creation remains denied by the syscall gate, so the current guest profile cannot create descendants.
- This narrow exit exception does not provide a general syscall broker or make the guest runtime usable for ordinary I/O.

## Stage H implementation boundary

- Capability delegation is explicit and per descriptor. The supervisor supplies pre-opened handles through `ExtraInfo::guest_capability_fds`; normal exec paths default to no grants. The loader passes the list to the kernel before staging the guest address-space switch.
- The kernel validates each descriptor and its access mode, retains only delegated handles, and closes all other descriptors as part of the atomic address-space transition. Loader-side pre-switch filetable scrubbing was removed so a failed preflight does not destroy the caller's descriptor table.
- The broker exposes only bounded read/write operations on explicitly delegated user-scheme, pipe, Serio and IRQ handles. This covers pre-opened filesystem streams, connected network streams, device streams and IPC pipes/user schemes. Path creation, arbitrary scheme calls, process creation, descriptor duplication and unrestricted device control remain denied.
- Guest cancellation uses the proc scheme's `guest-cancel` endpoint and the normal kernel force-kill scheduling path. The restricted syscall gate prevents guest-created processes and threads; pre-existing sibling contexts are terminated during activation, while the process manager accounts for guest threads through its normal wait/termination lifecycle.
- Guest crash and exit information is available through the proc scheme's `guest-crash` endpoint in the structured `CtxtStsBuf` format. The process manager separately translates guest faults into wait signals.
- Partial-load resources are held by RAII descriptor guards and address-space grant handles. Mapping failures explicitly unmap locally-created trampoline mappings where needed; dropping the grants handle releases the remaining mappings. Descriptor scrubbing is now performed by the kernel transition, after policy validation and outside the context lock, avoiding the earlier loader-side partial-filetable mutation window.
- Stage I and Stage J remain responsible for the broader Windows and macOS compatibility services. Stage H supplies the shared isolation boundary to both native launch paths; it does not claim those runtime services are complete.

## Security boundary

The bounded Rust interpreter model is not a hardware address space. Native freestanding images use actual Redox address spaces and user-mode contexts. The deny-by-default syscall boundary, isolated exit path, quotas, explicit read/write descriptor capabilities, cancellation control and guest crash report are kernel-enforced. The native loader grants no descriptors unless the trusted supervisor supplies them, and the broker intentionally exposes only bounded stream I/O. Stage H completion applies only to this restricted profile; it is not general-purpose safe execution of arbitrary untrusted PE/Mach-O applications.
